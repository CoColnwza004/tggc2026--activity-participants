# สะสมตรา ลุ้นรางวัล · TGGC 2569

เว็บกิจกรรมบูธ **การแข่งขันอัจฉริยภาพทางด้านภูมิศาสตร์และภูมิสารสนเทศแห่งประเทศไทย ระดับมัธยมศึกษา ครั้งที่ 3**
เสาร์ 28 พ.ย. 2569 · โรงเรียนชลประทานวิทยา จ.นนทบุรี

มี 3 เว็บแยกกัน ใช้ฐานข้อมูลเดียวกัน (Cloudflare D1):

## ประกาศจับรางวัล + แจ้งเตือนมือถือ
- **เจ้าหน้าที่เคาน์เตอร์แลกรางวัล** (เว็บเจ้าหน้าที่ → เคาน์เตอร์แลกรางวัล → ปุ่ม **📣 ประกาศจับรางวัล**): เลือกแบบ (ใกล้เริ่ม / เริ่มจับแล้ว / ประกาศผล / ข้อความอื่น) → สถานที่ (มีปุ่มลัด แก้ได้ที่ `EVENT.raffle.places`) → เวลา/ข้อความ (ถ้ามี) → ส่ง · มีตัวอย่างหน้าตาการแจ้งเตือนก่อนส่ง · กด "ยกเลิกประกาศ" เพื่อเอาป้ายออก
- **ผู้เข้าร่วม**: ทุกคนเห็นป้ายประกาศสีส้มด้านบนเว็บ · คนที่สะสมครบเปิดหน้าเว็บค้างไว้ ประกาศจะเด้งขึ้นพร้อมเสียง/สั่น ภายใน ~30 วินาที
- **ขอสิทธิ์แจ้งเตือนหลังสะสมครบ 23 บูธเท่านั้น** พร้อมบอกเหตุผล (แจ้งเมื่อเริ่มจับรางวัลและจับที่ไหน แม้ปิดหน้าเว็บ · ส่งเฉพาะเรื่องจับรางวัล) · เซิร์ฟเวอร์ก็รับสมัครเฉพาะสมุดที่ครบแล้ว
- Web Push มาตรฐาน (VAPID สร้างเองครั้งแรก เก็บใน D1 ไม่ต้องตั้งค่า) · ข้อความไม่ถูกส่งไปกับ push: มือถือดึงประกาศล่าสุดจาก `/api/announce` เอง · หน้าเจ้าหน้าที่ส่งเป็นชุด ชุดละ 100 เครื่อง (3 ชุดพร้อมกัน) · ส่งซ้ำ/กดซ้ำไม่แจ้งเตือนซ้ำ · เครื่องที่ยกเลิกแล้วถูกข้ามอัตโนมัติ
- รองรับ: Android (Chrome, Samsung Internet), คอม (Chrome/Edge/Firefox/Safari) · **iPhone/iPad ต้อง "เพิ่มไปยังหน้าจอโฮม" ก่อน** (iOS 16.4+, ในหน้าเว็บมีวิธีบอก) · เปิดจาก LINE/Facebook ใช้ไม่ได้ (บอกให้เปิดในเบราว์เซอร์)

## กันโกง
- QR ที่บูธเปลี่ยนทุก 30 วินาที (คล้าย OTP) ถ่ายรูปส่งต่อเพื่อนก็ใช้ไม่ได้ (รับย้อนหลังได้ไม่เกิน ~10 นาที เผื่อเน็ตหลุดตอนสแกน)
- 1 สมุด ยื่นตั๋วได้ 1 ครั้ง (บันทึกที่เซิร์ฟเวอร์ สแกนซ้ำ/สองเครื่องพร้อมกันก็ไม่ได้ใบจับฉลากเพิ่ม · จอเจ้าหน้าที่ขึ้น "ตั๋วนี้ใช้ไปแล้ว")
- การยื่นตั๋วทำได้จากเครื่องเจ้าหน้าที่เท่านั้น ผู้เข้าร่วมกดเองจากมือถือไม่ได้ · การจับฉลากทำด้วยกระดาษ ระบบไม่สุ่มรางวัล · ใส่รหัสผิดเกิน 15 ครั้ง/10 นาที ล็อกชั่วคราว · PIN ผิดเกิน 12 ครั้ง/15 นาที ล็อก

## รองรับคนเยอะ
- ไฟล์หน้าเว็บทั้งหมดเสิร์ฟจาก CDN ของ Cloudflare โดยตรง (ไม่นับโควตา Worker) มีเฉพาะ `/api/*` ที่วิ่งเข้า Worker
- ไฟล์ทุกไฟล์มี hash ในชื่อ → cache 1 ปี · CSS ฝังในหน้า · ตัวสแกน/สร้าง QR โหลดเฉพาะตอนกดใช้
- **ใช้ได้แม้เน็ตในงานล่ม**: เปิดเว็บครั้งแรกแล้ว เปิดซ้ำได้ทันที (service worker) · สแกนตอนไม่มีสัญญาณ ตราจะขึ้นก่อนแล้วส่งเข้าระบบให้เองเมื่อกลับมาออนไลน์ · จอ QR ของเจ้าหน้าที่สร้างรหัสได้แม้ออฟไลน์
- ประมาณการ 3,000 คน × 6 บูธ ≈ 25,000 คำขอ API — อยู่ในโควตาฟรีของ Workers (100,000/วัน) และ D1 สบาย ๆ

## แก้ข้อมูลงาน
ทุกอย่างอยู่ใน **`shared/event.js`** ไฟล์เดียว: รายชื่อบูธ (ชื่อ, ที่ตั้ง, สี, ไอคอน, ตำแหน่งบนผัง), เคาน์เตอร์แลกรางวัล, ข้อความใบจับฉลาก/ประกาศผล, ตัวอย่างของรางวัล (ใช้โปรโมทเท่านั้น), กำหนดการ, ผังงาน
> กำหนดการตรงกับกำหนดการฉบับจริงแล้ว (ย่อชื่อกิจกรรม) · ⚠️ ตำแหน่งเคาน์เตอร์แลกรางวัลยังไม่ยืนยัน · ถ้ามีรูปผังจริง วางไฟล์ใน `assets/` แล้วตั้ง `map.image`
> หลังเปิดให้สะสมตราแล้ว **อย่าเปลี่ยน `id` ของบูธ**

## Deploy (Cloudflare Workers + D1)
ครั้งแรก:
```bash
npm install
npx wrangler login
npx wrangler d1 create tggc2569-activity
```
คัดลอก `database_id` ที่ได้ ไปใส่ทั้ง `participant/wrangler.jsonc` และ `staff/wrangler.jsonc` แล้ว
```bash
npm run deploy
npx wrangler secret put STAFF_PIN -c staff/wrangler.jsonc
npx wrangler secret put ADMIN_PIN -c staff/wrangler.jsonc
npx wrangler secret put ADMIN_PIN -c admin/wrangler.jsonc
```
- ตารางในฐานข้อมูลสร้างเองอัตโนมัติเมื่อมีการใช้งานครั้งแรก
- ได้ URL เช่น `https://tggc2569-activity.<ชื่อบัญชี>.workers.dev` และ `https://tggc2569-activity-staff.<ชื่อบัญชี>.workers.dev`
- **นำ URL เว็บผู้เข้าร่วมไปใส่ `participantUrl` ใน `shared/event.js` แล้ว `npm run deploy` อีกครั้ง** (QR ที่บูธจะชี้ไปที่ URL นี้ — สแกนด้วยกล้องมือถือปกติก็เปิดเว็บและรับตราได้เลย)

แก้ไขครั้งต่อไป: `npm run deploy`

**ถ้า deploy ติดขั้นอัปโหลดไฟล์ (asset upload)** ใช้แบบฝังไฟล์ไว้ใน Worker แทน (ใส่ `database_id` ใน `wrangler.embed.jsonc` ด้วย):
```bash
npm run build && node scripts/build-embedded.mjs
npx wrangler deploy -c participant/wrangler.embed.jsonc
npx wrangler deploy -c staff/wrangler.embed.jsonc
npx wrangler deploy -c admin/wrangler.embed.jsonc
```

## รองรับคนได้แค่ไหน
- ยอดรวม (ตราแต่ละบูธ, ผู้เปิดสมุด, สะสมครบ, ยื่นตั๋ว) เก็บเป็นตัวนับในตาราง `counts` อัปเดตใน transaction เดียวกับข้อมูลจริง → จอบูธ/แดชบอร์ดอ่านไม่กี่แถว ไม่ต้องนับใหม่ทั้งตาราง (ตัวนับสร้างใหม่จากข้อมูลจริงอัตโนมัติเมื่อเปลี่ยนรายชื่อบูธหรือ `required`)
- มือถือที่รอยื่นตั๋วเช็ก `/api/ticket` (อ่าน 1 แถว) แทนการโหลดสมุดทั้งเล่ม
- รับตรา / เจ้าหน้าที่สแกนสมุด / ยื่นตั๋ว / เปิดสมุด = **คุยกับฐานข้อมูลครั้งเดียว** (transaction เดียว: บันทึก + ตัวนับ + ข้อมูลสมุดล่าสุด) · ทดสอบ 80 คนพร้อมกัน 960 คำขอ ไม่มี error ตัวนับตรงข้อมูลจริง
- ทุก API ส่ง header `server-timing: app;dur=<ms>` (เวลาใน Worker + ฐานข้อมูล) ไว้ดูความเร็ว
- แบบฝังไฟล์: รูปฝังเป็น binary (ไม่ต้องถอด base64 ทุกครั้ง) → ใช้ CPU ต่อคำขอน้อย (แผนฟรีจำกัด 10 ms)
- ฝั่งมือถือ: เน็ตช้าเกิน 6 วินาที หรือเจอหน้า error ของ Cloudflare → ตราเก็บในเครื่องก่อน แล้วส่งซ้ำอัตโนมัติ (ไม่หาย)
- แผนฟรีของ Cloudflare: ข้อจำกัดหลักคือ Workers 100,000 request/วัน (รีเซ็ต 07:00 เวลาไทย) ≈ 600+ คน · แผน Workers Paid ($5/เดือน) รองรับหลายพันคน

## ก่อนวันงาน (checklist)
1. แก้ `shared/event.js` → deploy
2. เตรียมที่เคาน์เตอร์แลกรางวัล: ใบจับฉลาก ปากกา กล่องจับฉลาก · ตอนจับรางวัล ตรวจชื่อผู้โชคดีได้ที่แอดมิน → รายชื่อผู้ยื่นตั๋ว
3. ทดลองครบ flow ด้วยมือถือ 2 เครื่อง (เครื่องหนึ่งเปิดจอบูธ อีกเครื่องสแกน)
4. แอดมิน → **ล้างข้อมูลทดสอบ** (พิมพ์ RESET) ก่อนเปิดงานจริง
5. พิมพ์ `poster/booths/booth-XX.pdf` ติดแต่ละบูธ (เจ้าหน้าที่สแกนเปิดจอบูธ) · ทำป้าย QR ลิงก์เว็บผู้เข้าร่วม ติดทางเข้า/โต๊ะลงทะเบียน (ให้คนเปิดเว็บครั้งแรกตอนเน็ตยังดี)
6. เจ้าหน้าที่ทุกบูธล็อกอินไว้ก่อนเปิดงาน · กด "เต็มจอ" · ตั้งไม่ให้จอดับ (ระบบขอ wake lock ให้แล้ว)
